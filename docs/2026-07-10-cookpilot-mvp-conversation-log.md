## 5. 기획심의서/평가의견에서 반영한 핵심

- CookPilot은 단순 레시피 검색 서비스가 아니라 실제 조리 중 코칭을 제공해야 한다.
- 주요 타깃은 20~39세 1인 또는 1~2인 가구, 자취생, 사회초년생, 신혼부부, 요리 초보자다.
- 심의 평가에서는 pain point 구체화와 기존 레시피 플랫폼 대비 차별성이 중요하다고 지적했다.
- 사용자는 조리 중 손이 자유롭지 않으므로 음성 UI와 큰 화면 안내가 중요하다.
- 조리 후 피드백을 다음 조리 레시피에 반영하는 개인 레시피 메모리 루프가 중요하다.

## 6. Figma/FigJam 분석에서 반영한 핵심

- 게스트 모드는 허용하되, 레시피 메모리 저장 시 로그인 유도가 필요하다.
- 조리 화면에는 현재 단계, 타이머, 음성 상태, 빠른 조작 버튼이 필요하다.
- 이전/다음 단계, 다시 듣기, 타이머 조작은 음성과 버튼 fallback 모두 필요하다.
- 조리 중 별도 입력 부담을 늘리기보다 음성 발화와 단계/타이머 이벤트를 자동 기록하는 방향이 적합하다.
- 조리 후에는 "나 맞춤 업데이트" 또는 "새 변형으로 저장" 같은 개인 레시피 버전 관리가 필요하다.

## 8. 확정된 제품 방향

CookPilot의 핵심 제품 방향은 다음과 같이 확정했다.

```text
조리 중 음성 기반 실시간 피드백
-> 조리 후 결과 피드백
-> 내 버전 레시피 수정
-> 다음 조리 때 개선된 레시피 제공
-> 반복할수록 개인화 강화
-> 개인 레시피 자산 축적과 락인
```

확정된 한 문장 정의:

```text
CookPilot은 조리 화면에서만 동작하는 STT/TTS 기반 음성 조리 모드로 레시피 단계를 진행하고,
단순 명령은 로컬에서 처리하며,
예외 상황은 LLM이 현재 단계 맥락으로 피드백한다.
조리 후 피드백은 개인 레시피 버전에 반영되어 다음 조리 때 개선된 레시피로 제공된다.
```

## 11. 음성 기능에 대한 결정

### 11.1 STT/TTS는 MVP 포함

- 사용자가 `sst`라고 표현했으나, 올바른 용어는 `STT`임을 정리했다.
- `STT`: Speech-To-Text, 음성을 텍스트로 변환
- `TTS`: Text-To-Speech, 텍스트를 음성으로 출력
- 사용자는 STT/TTS도 MVP 내용에 포함한다는 의견을 밝혔다.
- 최종적으로 STT/TTS는 MVP 필수 범위로 확정했다.

### 11.2 음성 수신 범위

음성 수신은 앱 전체에서 항상 켜지는 것이 아니라 조리 화면에서만 동작한다.

```text
앱 실행
-> 레시피 선택
-> 조리 시작
-> 조리 화면 진입
-> 음성 조리 모드 ON
-> 조리 중 음성 명령 수신
-> 조리 완료/중단/화면 이탈
-> 음성 조리 모드 OFF
```

지원:

- 앱이 켜져 있음
- 조리 화면이 활성화되어 있음
- 조리 세션 중임
- 마이크 권한이 있음
- 사용자가 말하면 STT로 인식하고 처리

미지원:

- 앱이 꺼져 있음
- 다른 앱 사용 중 음성 호출
- 잠금화면 음성 호출
- 백그라운드 상시 리스닝
- "쿡파일럿아" 같은 커스텀 호출어

### 11.3 Siri/Bixby와의 차이

- Siri/Bixby는 OS/제조사 레벨에서 저전력 wake word 감지를 한다.
- 일반 앱이 동일한 수준의 항상 듣기 또는 호출어 기능을 구현하기는 어렵다.
- CookPilot은 OS 전체 호출어가 아니라 조리 화면 안에서만 마이크를 열어두는 방식으로 충분하다고 판단했다.

## 12. 라면 예시로 정리한 핵심 동작

사용자가 라면을 끓이는 상황:

```text
1. 앱이 TTS로 말한다.
   "물 500ml를 넣고 3분간 끓이세요. 타이머를 시작합니다."

2. 유저가 특별히 말하지 않으면 로컬 타이머가 3분 카운트다운한다.

3. 3분 후 앱이 다시 말한다.
   "건더기, 분말스프, 면을 넣고 3분간 끓이세요."

4. 유저가 특별히 말하지 않으면 다음 3분 타이머가 자동 시작된다.

5. 중간에 유저가 말한다.
   "어, 지금 물이 안 끓어."

6. 이 발화는 로컬 명령이 아니므로 LLM에 현재 단계 맥락과 함께 전달된다.

7. LLM은 현재 단계 기준으로 답한다.
   "아직 끓지 않으면 1분 더 끓이고, 기포가 올라오면 다음 단계로 넘어가세요."
```

## 13. 로컬 처리와 LLM 처리 분리

### 13.1 로컬 처리

LLM을 호출하지 않고 앱 내부에서 즉시 처리할 명령:

- 다음
- 이전
- 다시 말해줘
- 지금 단계 알려줘
- 1분 더
- 타이머 멈춰
- 타이머 다시 시작

### 13.2 LLM 처리

현재 단계 맥락과 판단이 필요한 발화:

- 물이 안 끓어
- 너무 짜
- 싱거워
- 면이 덜 익었어
- 파가 없어
- 스프를 반만 넣었어
- 좀 더 끓여야 할까?
- 상한 것 같아
- 고기가 덜 익은 것 같아

## 14. 비용 관련 논의

- 사용자는 STT/TTS API 비용까지 발생하면 서비스가 감당하기 어려울 수 있다고 우려했다.
- 답변 방향:
  - 항상 듣고 항상 말하는 음성 AI 앱으로 만들면 비용과 구현 리스크가 크다.
  - CookPilot은 조리 화면에서만 음성 모드를 켠다.
  - 단계 진행, 타이머, 이전/다음/반복은 로컬 처리한다.
  - LLM은 판단이 필요한 예외 상황에만 호출한다.
  - TTS는 가능한 경우 기기 또는 브라우저 내장 TTS를 우선 고려한다.
  - STT도 조리 화면에서 짧은 발화 단위로 제한한다.
- 핵심 비용 원칙:

```text
조리 시간 전체에 AI 비용이 비례하는 구조가 아니라,
유저가 판단이 필요한 말을 했을 때만 LLM 비용이 발생하는 구조로 설계한다.
```
